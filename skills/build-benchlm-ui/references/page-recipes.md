# Page Recipes

Choose the smallest recipe that completes the user's task. Reorder or remove modules when the domain demands it.

## Leaderboard / Data Index

Use for ranked entities with filters and many metrics.

1. alert strip when a fresh update matters
2. sticky header
3. hero with direct scope statement
4. command search
5. top-three or summary panel
6. refresh/coverage/method metadata strip
7. optional verified updates or newsletter band
8. decision-ready picks
9. filter bar and result count
10. dense table
11. rank/evidence reading guide
12. dataset journal or change summary
13. comparison builder
14. category/workload exploration
15. compact methodology
16. evidence-rich footer

Critical behavior:

- Keep filter state shareable.
- Explain ranking and confidence separately.
- Let every row open a deeper evidence surface.
- Support CSV/JSON/export only when the underlying data is genuinely available.

## Model / Entity Profile

Use for one entity with metrics, provenance, and alternatives.

1. breadcrumb and identity header
2. status/evidence/freshness badges
3. primary score and one-sentence interpretation
4. price/context/runtime metadata strip
5. capability breakdown
6. exact-source benchmark table
7. evidence coverage and uncertainty note
8. release/version timeline
9. alternatives or related entities
10. sources and review date

Do not turn the profile into a marketing landing page. Unsupported claims must remain visibly separate from sourced measurements.

## Head-to-Head Comparison

Use for two entities and a decision.

1. compact comparison builder
2. verdict stating the recommended choice and decision condition
3. identity columns with equal visual weight
4. metric rows with exact units and winning-cell emphasis
5. evidence coverage row
6. task/category breakdown
7. price/performance interpretation
8. source details and caveats
9. related comparisons

Use muted tonal emphasis, not red-versus-green combat styling. Ties and missing evidence should be explicit.

## Provider / Category Directory

Use for browsing a medium-to-large entity catalog.

1. title and scope statement
2. featured directories or common paths
3. search
4. count/sort metadata
5. ruled card grid or compact directory list
6. related research or alert CTA
7. footer

Each card should expose the same meaningful fields. Hide dimensions that cannot be compared consistently.

## Methodology / Research Explainer

Use for technical trust content.

1. thesis hero
2. independence or disclosure note
3. two to four key principles
4. taxonomy/pillar overview
5. missing-data and uncertainty explanation
6. method version/hash/refresh strip
7. category sections with weighted vs display-only evidence
8. calibration and runtime sections
9. defaults, caveats, and source links
10. footer

Favor short sections and visible labels. Avoid decorative diagrams unless they materially clarify the method.

## Radar / Update Feed

Use for releases, pricing changes, deprecations, incidents, or changelogs.

1. hero with freshness promise
2. filter/search by provider, update type, or date
3. confirmed update count
4. chronological feed
5. source-confirmed badge and timestamp on every item
6. concise impact statement
7. source link
8. newsletter/subscription CTA
9. methodology for confirmation criteria

Incidents and unverified rumors must never share the same status treatment as confirmed releases.

## Interactive Tool

Use for calculators, prompt utilities, or selectors.

1. concise task statement
2. input form with examples and constraints
3. primary action
4. result panel with copy/export action
5. transparent calculation or method note
6. related tools
7. footer

Keep the form visually prominent, but do not use an oversized empty hero. Results should preserve inputs in the URL or local state when safe and useful.

## Mobile Composition

Across all recipes:

- Keep the decision/task above the first dense dataset.
- Collapse global search to an icon only if another visible path opens it immediately.
- Convert side-by-side comparison columns into stacked sections with repeated metric labels.
- Keep table identity context sticky or repeat it in each compact row.
- Put secondary filters in a disclosure or sheet.
- Avoid horizontal carousels for essential research content.
