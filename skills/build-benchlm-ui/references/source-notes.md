## Observable Implementation Signals

- Public CSS identifies Satoshi for body/UI, Cabinet Grotesk for display, and a monospace data stack.
- The main public container repeatedly uses a maximum width near 1120px.
- The desktop header uses a 66px navigation target and a sticky translucent panel surface.
- The home hero uses a display headline around `clamp(2rem, 4vw, 3rem)` with tight tracking and line-height.
- The public token system exposes warm HSL light surfaces, deep blue-black dark surfaces, a restrained teal accent, and separate provider colors.
- Public layouts repeatedly use hairline borders, 4–8px radii, tabular/mono metrics, compact metadata, and responsive behavior around 720px and 1040px.
- Public information architecture prioritizes current leaders, evidence strength, freshness, decision-ready picks, filters, full rankings, interpretation, methodology, and source-rich exploration.

## Interpretation Boundaries

- This skill describes patterns, not exact proprietary implementation code.
- Token values are useful references, not a requirement to impersonate the site.
- Do not redistribute BenchLM font files. Use properly licensed fonts or suitable alternatives.
- Do not copy the BenchLM logo, wordmark treatment, written content, rankings, benchmark data, or provider graphics.
- When applying the style to another brand, adjust accent color, typography, and identity details so the result remains distinguishable.
- Re-inspect the live site when a task requires exact current parity; the public design may change after the observation date.

## Distilled Product Principle

The strongest transferable idea is not a color palette. It is the coupling of editorial trust and data-product utility:

1. state the decision or current result;
2. show exact metrics and operational context;
3. label evidence strength and freshness;
4. make the underlying rows searchable and comparable;
5. disclose method and sources without interrupting the primary task.
